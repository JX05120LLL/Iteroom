# 自有 Harness 与选择性基础设施复用

> 状态：目标分工已确认；具体启动与接口形式待 R0 验证。2026-09-26。

Iteroom 以展示自研 Harness 工程能力为优先目标。采用用户确认的职责分工：Cordis 组织插件，DSH 核心负责模型/Loop，OCR 准备审查范围和规则，OpenSandbox 提供隔离执行；Iteroom 拥有任务、权限、快照、验证和审阅。整体 DSH 产品包装降低了工程所有权，完全自研 Loop/隔离运行时又会挤占任务可靠性工作，因此选择保留兼容引擎并构建自己的完整任务流程。

这一决定带来 Docker/沙箱服务前提、跨平台验证与多项目升级兼容责任，旧“仅 Node.js 即可完成全部操作”的承诺被替换。旧代码/数据保留为迁移基线；最小 DSH 支持组合验证后再收敛依赖，不把独立 Cordis 注册实验视为受支持发行入口。
