# R0 实际沙箱故障与网络切片

沿用用户已授权 OPENSANDBOX-PLAN：合成代码、无模型、最多两个串行应用沙箱，只改自己的临时服务，不重启 Docker、不挂载用户目录、不提交或推送。原工作区直接接续并保留，不能按技能默认步骤自动提交。

- [x] TDD：不授权即拒绝、服务归属/端口占用拒绝、网络缺少成功对照或降级不得通过、实际故障集成。
- [x] 受管服务控制器：核对安装根，受控环境启动，只按拥有的 PID/创建时间/命令行结束进程树；日志仅哈希。成功且资源确认后停本次服务；未知分配/清理失败保留控制服务和日志，禁止自动再启动。
- [x] 第一个合成沙箱：执行 ID/启动计数固定，重启控制服务再 reconnect/query、不重放；实际停服务使清理失败，Docker 证明仍存在，恢复后重试并双重清理核对。
- [x] 网络：读取真实 active/enforcement 状态；deny DNS→允许 example.com 的 DNS/TCP 成功→撤销规则后相同 IP TCP 拒绝。只 DNS 查询和 TCP 握手、不发送源码/HTTP正文；无对照成功则 unavailable/失败，不能声称断网。
- [x] 第二个串行沙箱：60 秒 TTL、120 秒命令，临近到期再次核对父子存活，等自动回收且未调用 kill，核对 API/Docker/卷消失。
- [x] 保存匿名结果与失败证据，复验相关/既有检查；同步所有当前文档。Gate C 收口需要基本运行与本故障报告共同满足，Gate A 真实模型仍缺授权。

Ruling：清理失败采用真实控制服务断连，而不注入 Docker daemon 内部故障——满足可恢复清理失败的端到端情景；不据此声明已验证存储损坏/daemon 删除失败。网络受控对照只临时允许单个公共域名，不开放 default allow。

独立审查提出两项重要问题并已修正：早期 running/短命令超时不够证明 TTL 停止活动进程；创建响应未知时应用标签扫描为空不够证明没有 egress/卷分配。对应补充红绿测试、临近到期实际父子证据及保守日志/控制服务保留。延迟分配分支是离线判定测试，没有声称实际注入该竞态。
