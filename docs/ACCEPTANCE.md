# Iteroom v1 验收矩阵

> 所有项目均为待执行要求。本轮文档检查不改变产品验收状态；实际结果写入 [STATUS](STATUS.md)。

## 1. 证据分类与记录

每次验收记录环境/平台、Node 版本、代码提交与工作区是否有未提交改动、模型路由、DSH/Cordis/OCR/SDK/服务版本、镜像 digest、输入快照、步骤、结果、日志/截图路径和未验证项。记录中只保存脱敏标识，不公开凭证或真实源码。

分别标注：源码核对、离线单元测试、模拟协议/模型、实际沙箱、真实模型端到端、干净环境发行检查。mock 成功不能升级为真实模型/沙箱通过；UI 截图不能证明执行安全。

| A10 | P0-09 | 用户选择审查问题后修复并复查 | 修复与原问题关联；复查使用新快照，旧结果不冒充新证据 |
| A11 | P0-10 | 前台/后台长命令及子进程取消、模型流取消 | 状态经历 cancelling；核对执行收束，未收束不报 cancelled |

| A13 | P0-11 | Host/服务重启、沙箱消失、网络断线和执行状态未知 | 可查看历史并核对；未知转 interrupted，不重放副作用命令 |
| A14 | P0-12 | 用户改动目标文件后接受补丁，含新增路径冲突 | 检出冲突，不静默覆盖；可导出或重新生成，Git index 不自动改变 |

| A19 | P0-01、P0-06 | 非回环访问、来源/令牌校验、恶意本地 API 请求 | 未授权请求不能读取/修改项目，日志不泄露凭证 |

## 3. 发布门槛

- P0-01 至 P0-14 都有通过证据；A01–A21 不存在未处理的核心失败。
- 三个真实流程完成，至少在声明的首发平台做干净环境检查；其他平台标为未验证。
- 模型、代码传输、保存位置、删除方式、第三方许可证和当前限制清楚。
- 模拟测试通过及构建成功不代替实际部署或发布验收。
- Git/npm 公开发布需当次明确授权；本文不构成提交、推送或发布授权。

## 4. 开发检查

当前已有 `npm.cmd run check`、`npm.cmd test`、`npm.cmd run build` 和 `npm.cmd run test:web`。按改动运行相关检查，新架构增加对应测试后再更新命令。纯文档变更检查 Markdown 本地链接、阶段一致性、事实边界和 `git diff --check`，无需强行运行模型或 Docker。

R0 独立检查使用 `node --test test/r0-dsh-contract.test.js test/r0-dsh-loop.test.js`；默认 npm test 未包含它们。[运行探针](r0/DSH-RUNTIME.md)证明官方 CLI 启动、合成只读工具、模拟错误/取消与已结束 Session 恢复，不据此将 A02、A04、A11、A13 等完整产品场景标为通过。
