# Iteroom 交付路线

> 2026-09-26 · 本文为阶段交付设计，不是已完成清单或未经审核的代码实施计划。每阶段先固定接口、验收场景，再实现最小切片。

## 1. 当前起点

已有 DSH Web 扩展、启动器、任务审阅和 Git 净变化证据，未完成新架构迁移。详见 [STATUS](STATUS.md)。旧 M0–M5 编号由本路线取代；不继续按旧路线提前接语音、RAG 和自动改进。

## 2. 顺序与退出条件

| 阶段 | 要交付的切片 | 退出条件 |
|---|---|---|
| R0：兼容性验证 | DSH 最小支持组合、OCR Delegate、OpenSandbox Docker 的独立 PoC | 三个 Gate 有实际证据、版本清单、限制和可复验步骤 |
| R1：自有任务与只读助手 | 自有 Host/插件组合、产品 API、任务存储、权限和文字 UI；复用 DSH 推理 | 真实理解任务可运行；无写入，刷新/重启不重复请求；引用可定位 |
| R2：隔离修改与验证 | 输入快照、沙箱工具、执行记录、停止/核对/清理、补丁导出 | 真实改一个小功能并测试；失败/断线/取消证据准确，本地仓库未被修改 |
| R3：用户接受与恢复 | 冲突检测、写回日志、部分失败恢复、接受/放弃、历史删除 | 保护脏工作树及外部编辑，取消/恢复无静默覆盖；补丁可导出 |
| R4：变更审查与关联修复 | OCR 准备、Iteroom 分组/预算/覆盖/定位、选择问题后修复与复查 | 三种审查输入可用；测试文件覆盖明确，问题有位置与依据；修复闭环可演示 |
| R5：v1 验收与交付 | 完整配置流程、故障提示、数据管理、支持矩阵、打包与归属 | P0 全部通过；声明的平台干净环境复验；公开发布另获授权 |

R0 的三个 PoC 可以独立准备，主产品按 R1–R5 顺序推进。每阶段结束同步 PRD、接口、UI 状态与 STATUS。这里定义整体路线，后续代码实施计划需针对当阶段拆分到具体文件和检查。

## 3. R0 三个 Gate

### Gate A：DSH

当前进度：[离线契约与 CLI 配置合成](r0/DSH-CONTRACT.md)、[官方 CLI 启动与模拟循环](r0/DSH-RUNTIME.md)已验证。自有合成只读工具、guard 拒绝、模型错误、Agent 取消与已结束会话的核心恢复有运行证据；真实模型、自有沙箱工具及执行恢复仍待验证，Gate A 未完成。SDK 无单任务取消、已有 Session 的 prompt 不能直接恢复，R1 Host 需使用对应核心公开接口。默认 sdk-minimal 带宿主持久 Shell，不能直接作为目标隔离模式。

- 固定当前 DSH/Cordis 基线；核对受支持的 Profile、Patch、服务导出与事件。
- 构建可运行的最小组合，注册一个 Iteroom 只读工具，再注册一个沙箱工具。
- 模型 → 工具 → 返回 → 下一步循环，检查取消、错误、Session 持久化和重启。
- 不留宿主执行逃逸入口，不直接使用内部 scheduler 构造第二个工具运行时。

### Gate B：OpenCodeReview

- 先无模型调用验证工作树、单提交、范围的 preview/rule JSON。
- 确认临时受管 Git 输入构造、重命名/删除和排除原因；记录 schema/version。
- 校验异常 JSON、进程超时、输出超限、规则失败和不可定位路径的处理。
- 测试源码需有覆盖策略；不把 Delegate 同规则分组当语义分组。

### Gate C：OpenSandbox

- 先无模型调用：创建 → 等待就绪 → 导入合成仓库 → 修改 → 测试 → 导出 → 删除/核对。
- 长命令包含子进程，分别验证前台/后台取消、断线、TTL、服务重启和清理失败。
- 显式设置网络、挂载、资源与凭证隔离；检查不支持/降级机制。
- 在 Windows 宿主真实验证 Docker/WSL2/Linux 环境，不以跨平台 SDK 推断部署成功。

真实模型请求与远程服务数据传输按用户授权范围执行；未经授权先做离线/合成数据验证。PoC 不读取真实项目凭证。

## 4. 既有代码迁移

| 当前文件/能力 | 处理 |
|---|---|
| `src/client/index.tsx`、样式与方案 C 资产 | 保留视觉、导航和禁用语音预览；逐步改接自有产品状态/API |
| `bin/iteroom.mjs` | 保留启动/回环绑定经验；新 Host 可运行后切换入口，不提前删旧启动器 |
| `src/index.js` | 旧 DSH 事件投影保持可运行；逐切片迁到自有任务/工具策略 |
| `src/host/task-store.js` | 保留兼容读取；新任务与旧 Session/turn 显式关联，新格式另存 |
| `src/host/workspace-evidence.js` | 复用路径、体积、Git 分类思路；净变化比较不能直接充当隔离补丁归属 |
| `iteroom.patch.yml` 和全量 DSH 依赖 | Gate A 通过且新入口验收后收敛到兼容最小组合 |
| `test/` | 保留现有测试，补充任务/权限/快照/沙箱/接受流程的真实变化测试 |

旧运行代码、构建产物和用户数据不能仅因新规划而清除。替换后清理旧模块必须以新流程验收、兼容/回滚说明及引用检查为前提。

## 5. 完成与评估

v1 提供三个完整演示：引用真实文件的代码理解；在脏工作树基础上隔离修改、测试和接受；审查明确变更、选择问题、修复及复查。另提供冲突、中断、失败和资源回收演示。

固定合成任务集和模型/预算/快照，报告成功率、问题定位准确性、审查覆盖、误报/漏报、检查耗时、取消收束时间与残留资源。和完整 OCR 对照时保持输入与模型条件可比，不直接引用厂商性能数字当本项目成绩。

文字版完成后，语音作为独立后续阶段重新定义需求；长期记忆、经验检索和策略改进分别评估，不在 v1 完成标准内。
