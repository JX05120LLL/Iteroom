# R1-2：受管任务的本机只读范围

本切片在 R1-1 已登记的 `understand` 任务上增加受限文件读取。它不启动 DSH、不发送模型请求，也不提供修改或执行能力。旧 DSH Web 工作台仍是独立的原有入口，不能据此称为全局只读模式。

## 接口与边界

- `POST /api/iteroom/managed-tasks/read` 由现有 DSH Web Connection 认证，另核对同源 Origin/Host，流式接收最多 8 KiB 的 JSON `{ "taskId": "...", "path": "..." }`；不允许其他字段或 query。只接受对应任务创建时精确选中的路径，项目根由服务端固定。
- 每次读取前、后逐段 `lstat`，拒绝符号链接、Windows junction、硬链接（链接计数大于 1）、目录和非普通文件；真实路径必须留在启动项目内。登记时还拒绝常见凭证文件名与扩展名，这不是对所有秘密内容的语义识别。单文件上限 256 KiB，严格 UTF-8 解码并拒绝 NUL。文件在读取期间发生可观察的身份/大小/时间变化时拒绝。
- 首次成功读取把路径、SHA-256、字节数、行数与时间记录到项目外受管任务 JSON，不保存正文。重复读取相同内容返回原记录；内容哈希变化返回 `READ_INPUT_CHANGED`，不覆盖旧证据。响应只回传本次读到的文本和定位元数据，`no-store`；错误不回显正文或本机路径。
- R1-1 旧任务文件没有 `readObservations` 字段时按空列表读取，首次记录时补写该字段；不迁移、不删除旧任务、旧 DSH Session 或旧证据。读取行为只写项目外任务元数据，不改用户项目。格式版本仍为 1，新增字段可选。

这不是 OS 原子快照：同权限本机进程在多次路径核验之间仍可竞争修改。哈希是已观察字节的身份，不保存原字节；以后接 DSH 工具前仍需固定可复读输入或安全的文件描述符/副本，并核对会话引用。当前不把它称作完整 `InputSnapshot`。

固定版 R0 探针已验证在独立 `sdk-minimal` Profile 中注册 `defineTool` 并只暴露自有工具；当前产品 Web Profile 仍暴露原 DSH 写入/执行工具。把读取工具直接注册到现有 Web Profile 不会形成受管只读模式，还需要隔离的受管引擎入口或经验证的按任务工具白名单，并把任务与 Session/turn 绑定。因此本切片仅提供 Host 读取能力，不让模型自动调用它。

## 验收与实施

1. 合成项目中选中普通文件能返回真实文本、行数和哈希；重建 Store 后元数据仍在。重复读取不增添记录，文件改变后拒绝。
2. 未选文件、越界/敏感路径、目录、链接或 junction、过大文件、二进制/无效 UTF-8、读取中变化和异常正文在内容返回前拒绝；被拒动作不产生读取记录。
3. 实际本机 Web carrier 验证未认证/跨源请求被拒、项目文件不变、模型 stub 请求数不增加；运行单元、类型、构建、Web smoke 和包内容检查。

实现位置：`src/host/managed-read-scope.js` 做文件核验，`ManagedTaskStore` 保存摘要，`managed-task-route.js` 暴露请求。后续切片把同一个受限读取能力注册为 DSH 自有工具，并建立 taskId/Session/turn、引用位置与取消恢复；本切片不将 HTTP 读取结果自动交给模型。
