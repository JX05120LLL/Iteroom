# R1 受管代码理解：真实模型验证记录

2026-09-28 在 Windows、Node v24.14.0、DSH/Cordis 固定发行 `0.1.5-rc.3` 上，用三座独立的一次性合成 Git 仓库验证受管只读入口。前两轮分别获批最多 4 次和 3 次 DeepSeek `deepseek-flash` 请求，每次最多 256 输出 tokens；修正后第三轮另获批最多 4 次、每次最多 512 输出 tokens。各轮人民币费用上限均为 5 元，只发送合成任务、选定文件片段和唯一只读工具 schema。密钥来自项目外本机配置，未写入仓库或报告。本次没有启动沙箱、OCR、宿主 Shell，也没有提交或推送。

## 前两轮失败结果

- 浏览器经已认证 Web 入口创建任务并启动。受管 DSH `sdk-minimal` 进程使用独立 `DSH_HOME`；模型确实调用了 `iteroom_read_snapshot`，工具清单没有写入/执行工具。任务最终为 `failed / ENGINE_TURN_FAILED`，**没有可确认的回答或引用，R1 的真实理解退出条件未通过**。
- 私有请求日志记录 **4 次尝试**，达到本轮授权次数上限，故停止进一步真实请求。该值是发送前持久预留次数，不代表服务商已计费次数或实际账单；没有核对服务商费用。每个请求的固定输出上限和正文上限由 Host 守卫检查，人民币 5 元是本地规划边界，不是服务商硬消费限额。
- 持久 DSH Session 显示前三次已完成的工具调用都请求一行合成文件的 `1–40`、`1–20`、`1–10` 行，旧工具因结束行超过 EOF 返回 `READ_LINE_RANGE_INVALID`。第四次预留后未获得可确认的完成事件。当时只修正 EOF 截断，仍先拒绝超过 120 行的**请求跨度**；官方 DSH 模拟模型回归覆盖了 `1–40` 请求，但没有覆盖模型随后请求 `1–200` 的情况。不能把该回归测试当作真实通过。
- 合成仓库的 `src/example.ts` 保持原始内容，Git 工作区干净。受管引擎的工具清单与结果来源由离线测试确认；本轮实际失败只证明模型到只读工具的调用和失败链路，不证明正确引用链路。

## 本机界面与恢复

实际浏览器确认方案 C 白色“代码理解”独立面板能创建任务、显示失败、不自动重发模型请求；刷新/重启后任务历史仍可查看。无凭证时启动返回 `MODEL_NOT_CONFIGURED`，任务保持待启动。390×844 窄屏界面和任务历史在合成仓库查看过；[窄屏截图](managed-ui-mobile.png)仅为合成 UI 证据，不证明安全或真实模型成功。项目外任务记录现在提供单调事件游标；旧记录缺事件时只补“已有状态”基线，不伪造先前事件。重启时未拥有的运行任务记为 `interrupted`，不自动重放相同任务。

本机另用模拟模型在实际子进程中等待，强制结束其 Host；固定版 DSH CLI 因 stdin 断开而退出，重新创建协调器只把原任务记为 `interrupted`，没有重发且合成源文件未变。这是 Windows/Node v24.14.0 的一次受管合成故障注入，不证明任意平台、真实提供方网络请求或未来沙箱子进程都能随 Host 退出。

4 次真实请求之后追加了独立文本增量通道：官方 `DeepSeekAdapter.prepareCall` 的 `text-delta` 经子进程第 4 管道回到 Host，合并到项目外任务草稿并写单调事件；UI 在运行中标为“尚未核实”，最终答案仍只取完成的 DSH turn 与真实工具引用。官方适配器在无 HTTP 的合成流、模拟 DSH Loop 和草稿存储单测通过。第二轮真实请求证实服务端产生并保存了多个增量片段；浏览器未捕获运行中的中间帧，不能称为实时视觉验收。

## 第二轮真实复验与后续修正

用户另授权最多 3 次请求、每次输出≤256 tokens、人民币 5 元上限。新合成 Git 仓库、新项目外 Home 和新任务经同一受管 Web 页面启动；持久请求日志恰为 **3 次预留**，达到新上限后停止。该轮第一次模型请求 `src/example.ts:1–200`，当时工具仍按“请求跨度不超过 120 行”拒绝；第二次改请求 `1–1` 并成功读到固定的一行内容。第三次服务端记录了文本增量，但 DSH Session 未得到可确认的最终 assistant message/turn 完成事件，任务仍为 `failed / ENGINE_TURN_FAILED`，不能展示为回答或引用。较长输出与 256-token 上限可能有关，但没有服务商用量或明确 finish reason，**这只是推断，不作为已确诊原因**。第二座合成仓库 Git 状态保持干净，服务已停止。

随后将工具改为**按实际返回**裁剪到 EOF、最多 120 行且≤16 KiB，模型即使请求 `1–200` 也只得到真实 `1–1`；提示中加入选定文件的准确行数和简短回答约束。官方 CLI+模拟模型对一行文件的 `1–200 → 1–1` 回归通过。修正晚于第二轮请求，**仍未有真实模型完成的证据**。两轮授权都已耗尽；请求预留数不是服务商已计费数，未核对账单。

## 第三轮真实成功与重启复验

新授权下将本任务上限明确设为最多 4 次请求、单次最多 512 输出 tokens；Host、子进程初始化、官方适配器及发送前磁盘守卫使用同一上限。对 512/513 tokens 和第四次/第五次请求的回环传输测试通过，超限在发送前拒绝。新的合成 Git 仓库只有一行 `src/example.ts`：`export const answer = 42`；经受认证的 Web API 建立并启动任务。私有请求日志记录 **2 次预留**，没有使用剩余 2 次额度。任务 `completed`，回答明确给出 `42` 和 `src/example.ts:1`；DSH Session 有 `turn/end: completed`、1 次 `iteroom_read_snapshot` 调用及 1 次成功结果，任务引用为该固定快照的第 1 行。经来源 API 核对快照 ID、哈希和内容，合成仓库前后 `git status --porcelain` 均为空，原文件 SHA-256 未变。

停止首个 Host 后，以相同项目外数据目录重新启动，浏览器能显示已完成的回答；点击引用展示固定来源第 1 行。[完成态与来源截图](managed-live-completed.png)只包含合成代码，[匿名结构化结果](managed-live-report.json)保留计数与限制。重启前后请求日志均为 2 次，未重发模型请求，Git 状态仍为空。浏览器在 390×844 窄屏下也能找到回答和来源；未捕获模型正在生成时的浏览器中间帧。第三轮实际有 1 条模型草稿事件，离线模型/本地合成流与任务存储测试覆盖增量管道；只能据此确认服务端增量持久化和最终浏览器呈现，不能称真实流式视觉链路全程已验。

本轮 `npm.cmd test` 53 通过、1 个 Windows 条件跳过；`npm.cmd run check`、`npm.cmd run build`、`npm.cmd run test:web` 通过。`npm.cmd pack --dry-run --json --ignore-scripts` 包含受管 Host、引擎与 UI 构建产物，只是清单检查，未做干净安装。服务商实际账单未核对，本地次数/tokens 守卫不是服务商人民币硬限额；第三轮的未用额度不会用于额外试验。

R1 的受管只读代码理解退出条件在**Windows、固定 DSH 版本、单项目/一次性合成文本**范围内通过。Iteroom 自有任务/快照/权限和结果记录由 Cordis 插件实现，现阶段仍借用 DSH Web 的认证 Connection 和完整开发界面；旧界面的宿主执行能力没有被移除，不能声称全产品已只读。真实提供方断线、其他平台、真实用户仓库、独立发行安装和 R2 修改/测试未验收。

## 复验

先核对新的授权、费用和合成输入；**不要沿用已经耗尽的前两轮 4 次/3 次或第三轮的剩余额度**。本机离线检查：

```powershell
node --test test/managed-engine.test.js test/managed-task-coordinator.test.js test/managed-task-store.test.js
npm.cmd test
npm.cmd run check
npm.cmd run build
npm.cmd run test:web
```

后续复验应使用新的合成 Git 仓库和项目外空数据目录，从受管入口建立任务，记录请求预留次数、真实工具结果、DSH turn/end、固定引用行、重启后的任务状态，以及仓库前后 `git status --porcelain`。第三轮成功证据不自动推广到真实用户代码或网络故障。
