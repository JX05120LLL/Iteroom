# R1-3：受管文字任务的固定输入

R1-2 只记录读取摘要，不能在源文件变化后重现模型所见内容。本切片为任务选定的 UTF-8 普通文件保存项目外副本，并按内容哈希验证每次读取。**本切片当时**不启动模型；后续受管引擎接线与真实失败见[记录](READONLY-LIVE.md)。旧 DSH Web Profile 从未变成只读入口。

## 接口与数据

- `POST /api/iteroom/managed-tasks/snapshot`：沿用现有 Connection Cookie 认证和同源检查，流式限制 8 KiB，仅接受 `{ "taskId": "..." }`。成功返回 manifest，不返回源码正文；调用后任务增加 `snapshotId`。重复调用返回原快照，不重新采集已变化的工作树。
- `managed-snapshots-v1/<projectId>/<taskId>/` 位于项目外数据目录。清单列出任务选定路径、SHA-256、字节数和行数；正文按清单顺序存为 `0.txt` 等。目录先在同级临时位置生成，再重命名到最终路径。创建后任务记录持有清单哈希；源文件变化不影响固定副本。
- `readManagedSnapshotFile(store, taskId, path)` 是后续 DSH 自有工具唯一允许的源码读取接口。它只接受任务选定路径，并在返回文本前核对清单、任务关联、文件类型、大小、身份与 SHA-256。缺失或损坏时失败关闭，不退回当前工作树。
- R1-1/R1-2 的旧 JSON 缺少 `snapshotId` 时仍可读取；首次捕获补写关联，不迁移或删除旧记录。若目录已写完而任务关联未落盘，重试校验旧目录后补写关联。任务记录或副本损坏不自动清空。

## 当前边界

每个文件复用 R1-2 的 256 KiB、UTF-8、路径与链接校验。多文件采集不是 OS 原子时间点；同权限进程在检查之间仍可能竞争改动。副本在应用层按哈希固定，并非操作系统不可更改的 WORM 存储。当前没有源码生命周期删除 UI；模型发送、Session/引用与取消已在后续受管链路接线，但真实模型任务尚未成功。快照可能含选定源码，保存在本机项目外数据目录，不能提交到仓库。

## 验证

`node --test test/managed-snapshot.test.js test/managed-task-route.test.js` 覆盖重启后读取、源文件变化、损坏拒绝、旧记录兼容、失败重试与路由输入边界。`npm.cmd run test:web` 经实际本机 Web carrier 验证未认证和跨源拒绝、快照关联重启保留、未调用模型及宿主项目不变。该证据不等于真实模型或 R1 阶段完成。
