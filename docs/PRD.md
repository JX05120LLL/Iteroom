# Iteroom 产品需求文档

> 版本：0.3 · 2026-10-09（目标范围不变，补充 R5-1/R5-2 配置与安装、R5-3 独立补丁契约的验证边界）
> 本文定义目标产品；现有代码与验收事实见 [当前状态](STATUS.md)。图片确认的职责分工取代旧版整套 DSH Web 产品复用路线。

## 1. 定位与目标

Iteroom 是面向个人开发者、本地优先的编程助手。用户通过文字理解代码、提出改动或审查变更；助手在独立执行环境中工作，提供补丁与实际验证证据，由用户决定是否写回项目。

项目首先作为工程作品，展示自己设计与实现 Harness 的能力。自研价值集中在任务编排、权限决策、代码快照、执行恢复、结果验证与用户审阅；推理循环、隔离运行时等基础设施选择性复用。第三方已有能力如实注明归属，不将换 Logo、SDK 转发或上游功能宣称为原创。

首个交付是可运行的文字编程助手，覆盖理解、修改、审查三个入口，共用同一个受管任务流程。审查与修复是重点场景，产品仍包含普通代码理解和小型功能开发。

## 2. 已确定的职责分工

| 项目 | 在 Iteroom 中的职责 | 取舍 |
|---|---|---|
| Cordis | 组织插件、依赖和生命周期 | Iteroom 定义插件组合，优先验证 DSH 配套的 Cordis 发行版 |
| DSH 核心 | 模型推理与 Agent Loop | 保留循环需要的服务契约及兼容实现，不复制另一套 Loop |

| Iteroom 自研部分 | 任务编排、权限决策、代码快照、结果验证、用户审阅 | 自有 Host、产品任务、工具策略、证据、补丁接受流程和 UI |

接入形式须通过 [架构与技术验证](ARCHITECTURE.md)。当前仍启动完整 DSH Web Profile；独立受管 R2 路径已接 OpenSandbox SDK/实际 Docker 沙箱，R4-1 的 OpenCodeReview 已接入产品审查准备，R4 已接原 DSH Loop 的预算审查、覆盖、定位及关联修复，[阶段退出验证](r4/COMPLETION-EVIDENCE.md)补齐生产 UI 中真实模型/实际沙箱组合。旧 Web Profile 的宿主工具不受 R2 路径约束。

R0 独立探针已验证官方 CLI、模拟模型的错误/取消与实际沙箱工具，以及[真实模型组合](r0/DSH-LIVE.md)：官方 deepseek-flash 经 DSH Loop 调用自有只读工具、实际沙箱修复/测试并读取结果，重启后未重放。Gate A/B/C 在固定环境与合成输入范围内通过。固定版 SDK 不包含单任务取消或已有会话的直接恢复入口；目标产品仍由 Iteroom Host 提供这些动作，驱动核心公开接口并核对执行。技术 Gate 不是产品任务、真实用户项目或 v1 交付。

R1-1 的[受管任务入口](r1/TASK-ENTRY.md)在现有已认证 Web Connection 上登记 `understand` 任务，保存项目外版本化记录、幂等 requestId 和单项目串行规则。R1-2 的[选定文件读取](r1/READ-SCOPE.md)可在本机读取任务范围内的普通 UTF-8 文件并记录哈希；它不调用模型或沙箱，也未提供可用的只读助手 UI。旧 DSH 页面仍是完整开发入口，不能由新接口推断其宿主工具已受控。

后续 [R2 受管隔离修改](r2/EVIDENCE.md)在固定 Windows/Node/DSH/OpenSandbox 版本及合成仓库中完成选定现有源文件的小功能修复、实际 `node --test`、项目外候选补丁、取消和资源清理。真实模型使用本轮授权的 4 次请求；最终代码的模型无关组合另经模拟 DSH Loop 和实际沙箱复验。文件新增/删除/重命名、实际提供方断线、用户项目、接受写回与发行仍按各自验收项推进；R2 限定证据不等于 P0-07 或 v1 全部满足。

[R3 接受切片](r3/EVIDENCE.md)已在一次性合成文件/Git 仓库中接入用户审阅、冲突预览、接受/放弃、逐文件写回检查点、重启后显式继续/回滚以及历史删除。脏工作树的固定快照与当前内容一致时可写回，外部编辑、目标缺失或恢复期间再编辑会拒绝覆盖；Git index/HEAD 不自动更改。实际 DSH Loop + OpenSandbox 配模拟模型生成的候选产物完成接受；本地浏览器验证下载、接受、回滚和删除。R3 最小退出条件仅在固定环境/现有选定文本范围内通过。真实模型对最新 R3 链路、真实断电、用户项目、新/删/重命名和发行仍待单独复验，不据此将 P0-07 或 v1 全量标为通过。

2026-10-01 的 [R3 自测与修复](r3/RETEST-2026-10-01.md)补充同一 Host 内的决策保护：同一任务的接受、放弃和恢复不能重叠，冲突请求不改变正在写回的归属；完成后的原请求重试仍幂等。最新实际沙箱/合成浏览器复测通过，模型请求为 0；这不提供多 Host 或跨编辑器的原子保证。

R1-3 的[固定输入](r1/INPUT-SNAPSHOT.md)把选定文件复制到项目外目录，任务记录关联 `snapshotId`，之后能在源文件变化时按哈希复读原文本。后续已接独立 `sdk-minimal` DSH 进程、单个自有只读工具、任务/Session 关联、引用校验和白色“代码理解”面板。[受管真实模型实测](r1/READONLY-LIVE.md)前两轮失败并驱动读取范围修正；第三轮在新合成仓库以 2 次真实请求完成答案、固定来源定位、浏览器查看及重启不重发，宿主项目未变。R1 受管只读退出条件在限定环境内通过。模型文本增量经独立进程管道写入任务事件，UI 轮询显示“生成中·尚未核实”；真实草稿事件已记录，浏览器生成中间帧仍未捕获。

当前开发版的受管模型预算默认每任务 3 次请求、单次 256 输出 tokens，可由本机启动环境在 1–4 次和 1–512 tokens 范围显式配置。R4-2 审查路径单独固定为 4 次/512 tokens。额度在发送前持久预留；它不是人民币硬限额，UI 尚未提供预算设置或账单展示。

## 3. 用户、范围与运行前提

R0 的[模型传输](r0/MODEL-TRANSPORT.md)与[私有计数](r0/MODEL-JOURNAL.md)先验证本机 HTTP/SSE、请求约束和磁盘预留；本轮在用户批准的 6 次、5 元上限内完成[真实组合](r0/DSH-LIVE.md)的 3 次请求。费用是本地保守预估，未核对提供方实际账单，也不是产品预算存储或服务商硬限额。后续真实请求仍须按新的授权范围执行。

2026-09-27 的 [OCR 独立切片](r0/OCR-DELEGATE.md)已验证固定 v1.12.9 Windows x64 的三种合成 Git 输入、排除原因及规则 JSON。默认测试排除可显式 include；删除与重命名旧侧由 Iteroom 补充定位与覆盖。后续[固定副本](r0/FIXED-REVIEW-COPY.md)已收口限定平台与输入边界内的 Gate B，未接正式审查或调用推理。

后续[审查输入切片](r0/REVIEW-INPUT.md)已补充受管合成输入的旧/新侧、完整 Git diff、分叉/初始/合并提交和空输入。删除由 Iteroom 保留旧侧待审，测试明确 include，二进制/链接拒绝或排除可见；未执行审查推理，正式不可变输入到 OCR 的接线仍待验收。

授权后的[实际沙箱切片](r0/SANDBOX-RUNTIME.md)已验证固定 SDK/服务/镜像下的导入、修改、测试、导出、前台/后台子进程取消、命令超时、客户端断线后显式停止与删除核对。[生命周期与网络切片](r0/SANDBOX-FAULTS.md)补齐临近 TTL 的父子进程核对、控制服务重启不重放、服务不可达后的清理重试及公开 IPv4 DNS/TCP 正向对照。Gate C 在固定环境和合成输入边界内通过；与 Gate A/B 合并满足本阶段 R0 技术验证，**v1 未完成**。产品运行前提不因此移除，网络结果不外推到全部协议/宿主隔离。

v1 面向有本地 Git 仓库的个人开发者，限单用户、单项目、串行任务。第一套完整演示项目使用 TypeScript/Node.js；其他语言仅在测试矩阵明确验证后列为支持。

目标入口是 npm 命令启动本地 Web 工作台，默认回环地址。首次配置包括模型提供方、项目范围、OpenSandbox 服务地址及权限策略。公开 npm 包尚未发布，目标入口不是当前安装承诺。

隔离修改和测试需要可连接的 OpenSandbox 服务、Docker 后端、任务镜像及项目依赖。Node.js 仅负责本地 Host/UI，不能独自提供沙箱。Windows 优先验证 Linux 沙箱与 Docker/WSL2 路径转换，Linux 作为后续发布候选。测试结果标注沙箱操作系统、镜像、依赖与命令，不外推为本机验证。OpenSandbox 的 Windows 客体能力不等于本机 Windows 部署已可用。

服务不可用时只允许受限只读操作并明确禁用修改/执行，不静默回退到宿主 Shell。启动只读页面无需创建沙箱。

v1 不包含实时语音、RAG、长期记忆、自修改 Harness、多用户、无人值守提交/推送、Kubernetes 或分布式调度。独立通话页保留为禁用的设计预览，完成文字版后再立项语音。旧版 M2–M5 不再是交付承诺。

## 4. 核心用户流程

### 4.1 理解代码

绑定项目 → 选择文件/代码范围 → 通过只读工具取得允许内容 → 流式回答并附文件位置。不产生写操作或 Shell 执行；上下文不足时说明缺口。

### 4.2 提出改动

1. 用户描述修改与验收要求，Host 建立任务和输入快照。
2. 纳入允许的已跟踪文件及用户确认的未跟踪文件，保留任务前未提交改动，展示排除/超限项。
3. 将快照导入独立沙箱，修改和执行仅通过受管工具进行。
4. 显示实时进展；额外联网、目录或预算需求进入权限等待。
5. 执行相关检查，导出相对于输入快照的补丁和验证记录。
6. 用户审阅；写回前重核本地目标文件与输入快照。冲突阻止覆盖，可重新生成或另存补丁。
7. 用户接受或放弃。接受不自动提交 Git，放弃不删除用户原有改动。

### 4.3 审查变更并修复

[R4-1](r4/EVIDENCE.md)实现下面的输入和规则准备：白色方案 C 的“变更审查”页面提供三种输入、固定 Diff、覆盖/排除原因、放弃和删除记录。历史修订必须为完整 40 位小写 SHA；工作树含暂存/未暂存/未跟踪，单提交采用第一父（根提交为空树），范围采用唯一 merge-base。删除文本旧侧与测试源码可纳入，依赖、敏感和二进制路径不保留准备正文。准备时任务保持 queued/not_started，不创建模型 Session；UI 显示“已固定 · 尚未推理”。R4-2 的开始审查动作单独创建原 DSH Session。终止或资源清理无法确认时持久阻塞，不能自动放弃、删除或重放。[R4-2 证据](r4/INFERENCE-EVIDENCE.md)覆盖预算、逐文件状态与候选定位：最多 2 组，每组编码上下文 8 KiB、总计 16 KiB；不截断完整文件/规则，超限保持待审。模型最多 4 次请求、每次 512 输出 tokens，严格返回分组 JSON；只有实际工具读过且显式报告的组才标已审。唯一 quote 由宿主产生行号，重复或失效片段保持未定位，所有发现均待人工确认。取消等待 CLI 退出，重启不重放，项目外 plan/result 与固定输入 Hash 绑定。真实 OCR/原 DSH CLI 配本地模拟模型已验，该段保留 R4-2 当时的开发切片范围；最新 [R4 阶段验证](r4/COMPLETION-EVIDENCE.md)已补真实模型和实际沙箱闭环，A08/A09/A10 完整矩阵仍未全量通过。

1. 用户选择工作树变更、单个提交或提交范围，固定审查输入。
2. OCR Delegate 提供候选文件、排除原因和规则；Iteroom 确定实际覆盖范围，补充需要审查的测试源码。
3. DSH 驱动审查推理，Iteroom 管理上下文预算、审查分组和结果合并。
4. 展示问题位置、依据、建议和覆盖清单，区分模型候选、位置已定位及有复现证据的问题。
5. 用户选择问题后建立关联修复任务，执行 4.2 的隔离修改与接受流程。
6. 在修复后的快照复查，展示原问题是否仍存在；零发现不等于全部代码正确。

[R4-3 限定实现](r4/FIX-EVIDENCE.md)通过审查候选创建关联 `modify`：只接受已定位的 new 侧 modified 普通源码，排除旧侧、删除、重命名及测试目标；目标整文件必须与固定发现一致。用户填写修复目标并选择已有测试，创建时固定输入但不启动模型/沙箱。任务可选 `reviewOrigin` 保存原审查、准备、报告、发现、路径和源码 Hash；开始修复仍沿用 R2，接受仍沿用 R3。接受后显式准备当前工作树全部变更，新 review 的 `recheckOrigin` 绑定修改任务与产物；源码和固定测试须与接受结果一致，新输入中的修改目标再次核对。恢复为 Git 无变更的目标暂明确拒绝，不以 no_changes 或旧报告替代复查证据；准备后需用户另行开始推理。目前显示独立复查报告，不自动把原候选标为已证实修复。取消/启动/历史删除等待同 Host 的关联准备收束；有子记录时阻止父记录删除。字段仍为 v1 可选，旧记录可读，回退旧程序前备份项目外数据；旧程序不提供新关系约束。此处为 R4-3 当时的 mock/合成收据范围；随后 [R4 阶段验证](r4/COMPLETION-EVIDENCE.md)经生产 UI 使用真实 DeepSeek 与实际 OpenSandbox 完成同一受管链路，预留 8 次请求。首次 3 个候选，复查仍有 2 个待人工确认候选；没有自动把原候选判为已证实修复。R4 最小阶段退出条件在 Windows/固定版本/合成现有文本范围内通过，完整 P0 与 v1 仍待 R5。

## 6. 任务状态与结果

产品任务主流程为 `queued → preparing → running → awaiting_review → applying → completed`。`running` 可进入 `waiting_approval`，批准后继续；执行失败进入 `failed`。活动阶段取消先进入 `cancelling`，确认收束后才是 `cancelled`。待审产物可以 `discarded`；重启无法判定执行状态时进入 `interrupted`，先核对再由用户恢复或重新生成。

`applying` 中断须在文件写回检查点停下并完成恢复核对，不能把半写回报告为取消成功。任务状态、检查结果、审查覆盖和资源状态分别记录；`completed` 不代表全部验证通过。失败或未验证的补丁可以进入审阅，接受时必须明确展示这些信息。

同一项目仅一个活动任务。追加要求保存为任务输入，不另启第二个 Loop。旧 DSH 事件与新任务状态有明确映射，不直接改写历史事件。

R1-1 的 `queued` 只表示任务登记；`engineStatus: not_started`、空 Session/Execution 关联明确表示没有运行。后续受管入口可显式启动或停止，只读任务在完成、失败、取消或中断后释放串行槽；同一任务不自动重发。产品任务保存独立事件序号与 DSH Session ID，重启可查历史；异常进程遗留的外部副作用核对属于后续阶段。该版本使用项目外 `managed-tasks-v1` JSON，与计划中的完整产品存储方案分开，无旧数据迁移。

R1-2 的读取摘要是文件被读取时的观察值，不保存正文，不等于可复读的固定输入快照。后续同一路径内容变化会拒绝，必须在引擎接线前补齐固定输入、来源定位和恢复语义；不能把仅有哈希的记录作为模型已看到的代码或任务完成证据。已有 R1-1 JSON 缺少新字段时按空读取记录兼容，不迁移或删除旧数据。

## 7. UI 与用户决策

视觉沿用 [方案 C](design-options/README.md)：白色背景、深绿色重点控件、双拱门 Logo。保持简洁，不在主流程堆积运行时细节。

[R5-1](r5/EVIDENCE.md)在代码理解、隔离修改和变更审查页加入白色折叠配置面板。显示缺失/无效/已配置的模型和沙箱配置、协调器实际请求/tokens 上限，以及用户显式触发的本机连接检查。配置读取不启动任务或模型；服务列表 API 成功仅标可连接，账户、镜像与执行均未由此验证。服务超时/失败有可见提示，刷新配置清除旧连接观察；凭证和原始异常不显示。该切片只提供状态查看，不提供凭证编辑、权限票据、人民币硬限额或完整 P0-01/P0-06 验收。

2026-09-27 确认 UI 以现有 DSH 的侧栏、会话、消息区与输入框为主体，Ant Design 局部补充任务状态、权限确认、补丁审阅、验证与配置；独立设计原型使用合成数据，尚未作为正式界面接入。

目标页面为项目/配置、文字工作台、任务详情与 Diff 审阅。工作台显示项目、选中范围、文字会话和状态；详情展示文件变化、审查问题、验证、权限和活动记录。窄屏折叠次要面板，保留状态和停止入口。

扩大权限、接受补丁、放弃产物与删除历史需明确用户决策。不可用按钮禁用并说明原因。独立通话页仅为白底预览，不启用麦克风或伪造字幕。

## 8. 数据、隐私与兼容性

[R5-2](r5/INSTALLATION-EVIDENCE.md)验证本机 Windows 仓库外 tarball 消费项目，安装后启动生产入口/UI，无源码 checkout 链接。该范围只有缺配置、认证及未启动取消恢复，不等于首次配置成功、真实模型/沙箱任务或干净机器发行。未启动理解任务可取消；取消须等快照准备收束，历史删除在另有活动任务时失败关闭。新取消状态保留 v1 结构，旧记录继续可读；旧程序可能不认识新状态，降级先停止服务并备份全部项目外数据，详细回退步骤见上述证据。三条流程、方案 C 和禁用通话预览保持既定范围。

[R5-3](r5/PATCH-EVIDENCE.md)补 P0-07 的独立 v2 数据契约：明确不存在/空文件、新增/修改/删除/重命名、预先批准路径、内容与产物限额，以及冲突和显式继续/回滚计划。一次性合成 Git 验证导出补丁的应用与反向恢复；恢复状态为纯数据测试，不是实际磁盘恢复。产品 API、任务存储、沙箱工具与 UI 尚不调用 v2，当前修改入口仍只修改选定现有文本，旧 v1 保存拒绝 v2 并保持冷读。没有用户数据迁移；完整 A05/A14/A15/A18、R5 与 v1 未通过。下一步先做独立 v2 安全快照/产物存储，再接操作批准、沙箱与接受流程。

本地优先不等于离线：代码可能发送给所选模型；使用远程沙箱时，快照也会传到该服务。配置页说明这两条数据路径。

宿主保留模型和沙箱凭证，沙箱仅取得必要代码及经批准的依赖访问。默认排除 `.env`、凭证、宿主用户目录、`.git` 管理数据与设备路径；`.gitignore` 不是唯一保护。测试源码按任务需要纳入，不能直接照搬 OCR 的排除默认值。

快照和日志可能含源码，存于项目外的数据目录，提供保留期限、删除和容量限制。删除待审产物前允许导出；进行中或待恢复资源不无条件清理。

旧 DSH 会话及现有任务数据保留原格式/位置，新任务记录版本化，不将旧事件包装成新架构已验证任务。格式升级先备份和校验，失败保留旧格式可读入口。

## 9. 工程亮点与完成标准

1. **工作区保护**：脏工作树快照、隔离修改、补丁导出、冲突检测和受控写回。
2. **任务生命周期**：权限等待、取消确认、未知状态恢复、执行去重和资源清理。
3. **证据关联**：审查覆盖、代码定位、命令结果、环境和失败原因与输入快照关联。

每个切片提供接口、不变量、失败场景及可重复验收，上游功能归属透明列出。

v1 完成条件：陌生开发者在声明的平台按文档启动，完成理解/修改/审查三个真实流程；能停止和恢复、保护冲突文件、识别未验证结果，并接受或放弃补丁。全部 [P0 验收](ACCEPTANCE.md) 与 [交付路线](ROADMAP.md) 完成后才称为可公开使用版本。
