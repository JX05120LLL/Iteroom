# Iteroom 产品需求文档

> 版本：0.2 · 2026-09-26
> 本文定义目标产品；现有代码与验收事实见 [当前状态](STATUS.md)。图片确认的职责分工取代旧版整套 DSH Web 产品复用路线。

## 1. 定位与目标

Iteroom 是面向个人开发者、本地优先的编程助手。用户通过文字理解代码、提出改动或审查变更；助手在独立执行环境中工作，提供补丁与实际验证证据，由用户决定是否写回项目。

项目首先作为工程作品，展示自己设计与实现 Harness 的能力。自研价值集中在任务编排、权限决策、代码快照、执行恢复、结果验证与用户审阅；推理循环、隔离运行时等基础设施选择性复用。第三方已有能力如实注明归属，不将换 Logo、SDK 转发或上游功能宣称为原创。

首个交付是可运行的文字编程助手，覆盖理解、修改、审查三个入口，共用同一个受管任务流程。审查与修复是重点场景，产品仍包含普通代码理解和小型功能开发。

## 2. 已确定的职责分工

| 项目 | 在 Iteroom 中的职责 | 取舍 |

| Iteroom 自研部分 | 任务编排、权限决策、代码快照、结果验证、用户审阅 | 自有 Host、产品任务、工具策略、证据、补丁接受流程和 UI |

接入形式须通过 [架构与技术验证](ARCHITECTURE.md)。当前仍启动完整 DSH Web Profile，OpenCodeReview、OpenSandbox 尚未接入。

R0 已在独立探针中验证官方 CLI 启动、模拟模型与自有合成只读工具。固定版 SDK 不包含单任务取消或已有会话的直接恢复入口；目标产品仍由 Iteroom Host 提供这些动作，驱动核心公开接口并核对执行。此证据不代表真实模型、沙箱或产品任务能力已交付，详见 [R0 运行结果](r0/DSH-RUNTIME.md)。

## 3. 用户、范围与运行前提

v1 面向有本地 Git 仓库的个人开发者，限单用户、单项目、串行任务。第一套完整演示项目使用 TypeScript/Node.js；其他语言仅在测试矩阵明确验证后列为支持。

目标入口是 npm 命令启动本地 Web 工作台，默认回环地址。首次配置包括模型提供方、项目范围、OpenSandbox 服务地址及权限策略。公开 npm 包尚未发布，目标入口不是当前安装承诺。

隔离修改和测试需要可连接的 OpenSandbox 服务、Docker 后端、任务镜像及项目依赖。Node.js 仅负责本地 Host/UI，不能独自提供沙箱。Windows 优先验证 Linux 沙箱与 Docker/WSL2 路径转换，Linux 作为后续发布候选。测试结果标注沙箱操作系统、镜像、依赖与命令，不外推为本机验证。OpenSandbox 的 Windows 客体能力不等于本机 Windows 部署已可用。

服务不可用时只允许受限只读操作并明确禁用修改/执行，不静默回退到宿主 Shell。启动只读页面无需创建沙箱。

v1 不包含实时语音、RAG、长期记忆、自修改 Harness、多用户、无人值守提交/推送、Kubernetes 或分布式调度。独立通话页保留为禁用的设计预览，完成文字版后再立项语音。旧版 M2–M5 不再是交付承诺。

## 4. 核心用户流程

### 4.1 理解代码

绑定项目 → 选择文件/代码范围 → 通过只读工具取得允许内容 → 流式回答并附文件位置。不产生写操作或 Shell 执行；上下文不足时说明缺口。

### 4.2 提出改动

1. 用户描述修改与验收要求，Host 建立任务和输入快照。
2. 纳入允许的已跟踪文件及用户确认的未跟踪文件，保留任务前未提交改动，展示排除/超限项。
3. 将快照导入独立沙箱，修改和执行仅通过受管工具进行。
4. 显示实时进展；额外联网、目录或预算需求进入权限等待。
5. 执行相关检查，导出相对于输入快照的补丁和验证记录。
6. 用户审阅；写回前重核本地目标文件与输入快照。冲突阻止覆盖，可重新生成或另存补丁。
7. 用户接受或放弃。接受不自动提交 Git，放弃不删除用户原有改动。

### 4.3 审查变更并修复

1. 用户选择工作树变更、单个提交或提交范围，固定审查输入。
2. OCR Delegate 提供候选文件、排除原因和规则；Iteroom 确定实际覆盖范围，补充需要审查的测试源码。
3. DSH 驱动审查推理，Iteroom 管理上下文预算、审查分组和结果合并。
4. 展示问题位置、依据、建议和覆盖清单，区分模型候选、位置已定位及有复现证据的问题。
5. 用户选择问题后建立关联修复任务，执行 4.2 的隔离修改与接受流程。
6. 在修复后的快照复查，展示原问题是否仍存在；零发现不等于全部代码正确。

## 5. v1 功能与验收要求

| ID | 能力 | 可验收结果 |
|---|---|---|
| P0-01 | 项目与配置 | 显示项目、模型及沙箱状态；错误配置有恢复方式，凭证不写入项目 |
| P0-02 | 自有 Host | Iteroom 拥有任务入口与产品状态，DSH 核心驱动推理；注册成功不视为完整接入 |
| P0-03 | 文字理解 | 流式回答、范围选择、文件引用；只读任务没有写入/执行副作用 |
| P0-04 | 代码快照 | 包含确认内容，记录内容哈希与排除原因，默认禁止凭证路径 |
| P0-05 | 隔离执行 | 文件、命令和测试归属指定沙箱，默认禁止未批准的宿主执行 |
| P0-06 | 权限与预算 | Host 执行范围、网络、时长和输出限制；拒绝后未发生受拒动作，批准有明确作用域 |
| P0-07 | 修改与补丁 | 新增、修改、删除和重命名可审阅，补丁描述相对输入的变化，超限项不被隐去 |
| P0-08 | 真实验证 | 显示执行 ID、命令、cwd、环境、退出码和日志；超时/取消/证据不足不显示通过 |
| P0-09 | 变更审查 | 支持工作树、提交和范围，显示排除/完成/失败项，校验问题位置与重复结果 |
| P0-10 | 任务控制 | 追加指令归属当前任务，取消后确认模型与执行收束，保留已产生证据 |
| P0-11 | 恢复 | 重启能查看历史并核对沙箱，不自动重放执行状态未知的副作用命令 |
| P0-12 | 接受与放弃 | 接受前重核文件，部分写回失败可识别并恢复；放弃不改本地项目 |
| P0-13 | 数据管理 | 可查看保存位置、删除历史及产物；清理进行中任务需先收束执行 |
| P0-14 | 工程交付 | 声明的平台完成真实任务，离线/模拟/真实模型/实际沙箱/发行验证分开记录 |

详细场景见 [验收矩阵](ACCEPTANCE.md)。退出码为零只证明该检查成功退出；没有测试结果时不编造用例通过数。

## 6. 任务状态与结果

产品任务主流程为 `queued → preparing → running → awaiting_review → applying → completed`。`running` 可进入 `waiting_approval`，批准后继续；执行失败进入 `failed`。活动阶段取消先进入 `cancelling`，确认收束后才是 `cancelled`。待审产物可以 `discarded`；重启无法判定执行状态时进入 `interrupted`，先核对再由用户恢复或重新生成。

`applying` 中断须在文件写回检查点停下并完成恢复核对，不能把半写回报告为取消成功。任务状态、检查结果、审查覆盖和资源状态分别记录；`completed` 不代表全部验证通过。失败或未验证的补丁可以进入审阅，接受时必须明确展示这些信息。

同一项目仅一个活动任务。追加要求保存为任务输入，不另启第二个 Loop。旧 DSH 事件与新任务状态有明确映射，不直接改写历史事件。

## 7. UI 与用户决策

视觉沿用 [方案 C](design-options/README.md)：白色背景、深绿色重点控件、双拱门 Logo。保持简洁，不在主流程堆积运行时细节。

2026-09-27 确认 UI 以现有 DSH 的侧栏、会话、消息区与输入框为主体，Ant Design 局部补充任务状态、权限确认、补丁审阅、验证与配置；独立设计原型使用合成数据，尚未作为正式界面接入。

目标页面为项目/配置、文字工作台、任务详情与 Diff 审阅。工作台显示项目、选中范围、文字会话和状态；详情展示文件变化、审查问题、验证、权限和活动记录。窄屏折叠次要面板，保留状态和停止入口。

扩大权限、接受补丁、放弃产物与删除历史需明确用户决策。不可用按钮禁用并说明原因。独立通话页仅为白底预览，不启用麦克风或伪造字幕。

## 8. 数据、隐私与兼容性

本地优先不等于离线：代码可能发送给所选模型；使用远程沙箱时，快照也会传到该服务。配置页说明这两条数据路径。

宿主保留模型和沙箱凭证，沙箱仅取得必要代码及经批准的依赖访问。默认排除 `.env`、凭证、宿主用户目录、`.git` 管理数据与设备路径；`.gitignore` 不是唯一保护。测试源码按任务需要纳入，不能直接照搬 OCR 的排除默认值。

快照和日志可能含源码，存于项目外的数据目录，提供保留期限、删除和容量限制。删除待审产物前允许导出；进行中或待恢复资源不无条件清理。

旧 DSH 会话及现有任务数据保留原格式/位置，新任务记录版本化，不将旧事件包装成新架构已验证任务。格式升级先备份和校验，失败保留旧格式可读入口。

## 9. 工程亮点与完成标准

1. **工作区保护**：脏工作树快照、隔离修改、补丁导出、冲突检测和受控写回。
2. **任务生命周期**：权限等待、取消确认、未知状态恢复、执行去重和资源清理。
3. **证据关联**：审查覆盖、代码定位、命令结果、环境和失败原因与输入快照关联。

每个切片提供接口、不变量、失败场景及可重复验收，上游功能归属透明列出。

v1 完成条件：陌生开发者在声明的平台按文档启动，完成理解/修改/审查三个真实流程；能停止和恢复、保护冲突文件、识别未验证结果，并接受或放弃补丁。全部 [P0 验收](ACCEPTANCE.md) 与 [交付路线](ROADMAP.md) 完成后才称为可公开使用版本。
