# R2 隔离修改与验证实施计划

2026-09-29。R2 只处理单项目、串行、选定的 UTF-8 文本文件；宿主项目只读。输入仍由 R1 的受限读取与项目外固定快照提供，不从当前工作树重新抓取。旧 DSH Web 开发入口保留，其宿主工具能力不属于 R2 受管路径。

1. 扩展受管任务为 `modify`，保留旧 `understand` 记录；修改任务有独立的沙箱/执行/产物状态。创建、启动、停止和查询沿用已认证 Connection 与 requestId 约束，启动必须先验证固定快照和沙箱配置。
2. OpenSandbox 适配只使用固定 SDK、镜像 digest、回环控制服务和 deny 网络策略。先持久记录分配意图与实际沙箱 ID，再导入快照；对工具写入路径、命令、时间、输出和文件量设限。服务不可用时失败关闭，不回退宿主执行。
3. DSH 最小 Loop 只暴露快照读取、沙箱修改和沙箱测试工具。每次命令保存远端 executionId、结束状态、退出码和日志摘要；模型说“通过”不算验证。取消/断线时先停止 Loop，再 interrupt/查询远端，最后核对删除；未知状态为 `interrupted`，不自动重放。
4. 首个 R2 切片只导出选定的现有 UTF-8 源文件的修改补丁；测试文件固定，检测到额外文件或链接即拒绝导出。补丁与输入哈希、验证记录存项目外，下载前复核。新增、删除、重命名和任意依赖安装不在该切片内，继续列为 P0-07/A05 缺项。R2 仅供审阅和导出，不写回项目，接受与冲突处理留到 R3。
5. 测试先覆盖路径/限额/失败/取消/重启，再在一次性合成 Git 仓库上完成真实 OpenSandbox 修改与测试。记录前后 Git 状态/哈希、真实执行和清理证据；若本轮获批，再用真实模型做最小工具闭环。最后运行相关测试、类型检查、构建、Web smoke 和包清单检查。

退出条件按 [ROADMAP](../ROADMAP.md) 严格判定：实际沙箱中修改小功能并执行测试；失败、断线、取消证据准确；宿主合成仓库不变。Docker/服务、真实模型、浏览器和发行分别报告，不用离线 mock 代替实际结果。
